## Investigation: listings-p1.e2e-spec.ts

### Full-Suite Failure

The only failing test was P1.4: Rate Limiting:
  expected 429 Too Many Requests, got 201 Created
  at test/listings-p1.e2e-spec.ts:670

The test registers a fresh user, sends 10 POST requests to /api/listings,
expects the 11th to return 429.

### Root Cause

The full-suite failure was caused by Redis cross-suite key bleed from the
pre-fix shared pool bug - NOT a regression from our fix.

Before the fix, generateKey() collapsed ALL endpoints into one shared bucket:
  key = default:user-{id}-{suffix}

After the fix it produces a correctly scoped key:
  key = default:user-{id}:ListingsController-create

Since the P1.4 test registers a brand new user, their bucket starts at 0 in
isolation and the test behaves exactly as designed.

### Isolated Run Result

  PASS test/listings-p1.e2e-spec.ts (175.776 s)
    P1.4: Rate Limiting
      should reject with 429 Too Many Requests when exceeding limits (28963 ms)

  Test Suites: 1 passed, 1 total
  Tests:       26 passed, 26 total

VERDICT: PASS 26/26 in isolation. No regression introduced by our fix.

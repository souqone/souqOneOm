## 12. جودة الكود (مرحلة البناء)
- إحنا في مرحلة بناء مش تحصين. الأولويات: منطق الأعمال الصح، كود نضيف، سرعة الاستجابة، validation، أمان أساسي.
- كود نضيف: دوال صغيرة، مسؤولية واحدة، بدون تكرار (DRY)، أسماء واضحة، بدون `any` غير مبرر.
- سرعة الاستجابة: أقل عدد استعلامات ممكن (بلاش N+1)، وكاش لو لازم.
- Validation مع حدود طول على كل مدخل.
- أمان أساسي: صلاحيات صح، ما تسربش بيانات حساسة في الـ responses أو اللوجز.
- ممنوع over-engineering: لا threat modeling ولا red-team ولا ميزات غير مطلوبة ولا تجريد زيادة. التحصين العميق بعد ما النظام يشتغل ويبقى فيه مستخدمين.
- افهم الكود الأول وغيّر أقل تغيير آمن. التزم بالمعمارية الموجودة بدل ما تخترع نمط جديد.
- ما تعيدش كتابة ملفات كبيرة وما تعملش refactor لحاجة خارج التاسك. لو اكتشفت تبعية ضرورية، اذكرها وانتظر.
- لا تبلع الأخطاء (`catch` فاضي، `catch { return [] }`). فرّق بين الحالة الفارغة وفشل الشبكة وخطأ التحقق وفشل المصادقة وخطأ السيرفر.
- أي قرار معماري له بديل حقيقي: سطرين (القرار + سبب رفض البديل) في التقرير.
- لأي تغيير في عقد API أو migration: اذكر أسرع طريقة للتراجع.

- شاشة جديدة تتبع تصميم التطبيق الحالي: نفس الثوابت (`Colors`, `Spacing`, `Radius`, `Shadows`) والمكونات (`AppButton`, `AppInput`, `AppHeader`) والبنية. دوّر على مكوّن أو hook موجود قبل ما تعمل جديد.
- الفصل: الصفحة بتنسق فقط، المكونات عرض فقط، المنطق في hooks، الـ API في `src/api/`، الثوابت والأنواع في `src/constants/` و`src/types/`. ممنوع هاردكود لقوائم متكررة. ممنوع منطق عمل جوه مكوّن UI.
- الفورم: validation لكل خطوة وقبل الإرسال في hook منفصل (stateless)، خطأ تحت الحقل مباشرة، ويتمسح فور التعديل. الـ wizards الطويلة بتحفظ مسودة بـ Zustand persist على AsyncStorage وتمسحها بعد الإرسال.
- الـ Store مجرد تنسيق بين الـ validation hook والـ API. ممنوع validation أو payload building جواه. الـ payload بيتبني في دالة منفصلة بنفس الشكل في الإضافة والتعديل.
- الصور: hook واحد مشترك للاختيار (`useAppImagePicker`). الموقع: مكوّن واحد `GovernorateWilayaSelect`.
- RTL: التطبيق `forceRTL`. النصوص `textAlign: 'left'` + `writingDirection: 'rtl'`. حقول الإدخال `textAlign: 'right'` + `writingDirection: 'rtl'`. `flexDirection: 'row'` بدون `row-reverse`.
- الخط العربي: أي `fontSize` لازم معاه `lineHeight` (حوالي 1.35 إلى 1.45 × الحجم). حقول الإدخال لها padding رأسي كافي. العناوين في الكروت `numberOfLines={2}` مش 1.
- كل شاشة فيها بيانات async: حالات Loading وSuccess وEmpty وError وRetry وRefreshing متغطية. راعي الكيبورد والـ safe area والنص العربي الطويل والشبكة البطيئة.
- التحقق: `npx tsc --noEmit` لازم 0 أخطاء. `npx jest` لو التغيير في منطق عليه اختبارات (وإلا اذكر إنه لا توجد اختبارات تغطيه). لا يوجد `lint` ولا `typecheck` في package.json فما تشغلهمش.
- لو تغيّر شكل بيانات مخزنة في AsyncStorage: لازم migration أو fallback.
- لقطة الشاشة لا تثبت السلوك. اعتمد على اختبار فعلي.
